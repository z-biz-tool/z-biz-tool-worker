## 5.1 阶段一 · P0 子进程生命周期（本仓独有的高危面）

`agent_proxy.rs` 直接用 `std::process::{Child, Command, Stdio}` 拉起 agent-proxy，
且它自己还会再拉起 claude / hermes / opencode 三个 CLI。
现有 9 条 `agent_proxy` 测试只覆盖「起得来 / 杀得掉 / 杀得对」。

| 任务 | 内容 | 关联 | 状态 | 验收标准 |

| W-02 | `which node` 依赖外部 PATH：PATH 被改 / node 不在 PATH 时的行为明确化 | 00 · P0-2 | **未落地** | 有单测覆盖「PATH 里没有 node」与「PATH 为空」两种输入 |
| W-03 | stdout/stderr 无上限：子进程输出量大的内存与背压行为 | 00 · P0-3 | **未落地** | 有单测覆盖「子进程输出 > 1MB」时的行为，且实现有上限或明确的背压 |

## 5.7 兼容与回滚原则

1. **文档类改动**：`git revert` 单 commit 即可回滚，零运行时风险。
2. **纯逻辑抽取**（W-05 / W-14 / W-15）：抽出的模块与原实现**逐行等价**，
   等价性由测试钉住；回滚 = 把组件改回内联实现。
3. **数据库写路径**（W-07～W-12）：把「读-改-写」换成**带 WHERE 的单条 UPDATE**，
   语义是"条件不成立就明确失败"，不是"静默覆盖"。
   回滚需要同时回滚 `db.rs` / `storage.rs` / `commands.rs` 三处。
4. **门禁收严**（W-21）：clippy 从 advisory 转 `-D warnings` 是**收紧**，
   回滚只需去掉 `-D warnings`。
5. **产品行为**：本轮**没有**新增任何用户可见的约束或限制；
   唯一的用户可见变化是 W-10/W-11 修掉的两处**状态不一致**（任务挂着已释放的 Agent / 旧 Agent 卡在 working）。
