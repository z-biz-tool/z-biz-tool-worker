### B3 ✅ 已闭合（2026-10-19）：并发领取竞态

> **闭合经过**：查清了，而且**是真的有竞态**。
> 原 `assign_task` 是「find_task → 改内存 → save_task」三步，而 `save_task` 是
> **无条件 upsert**（`ON CONFLICT DO UPDATE` 不带 WHERE）⇒ 两个 Agent 同时领同一个任务时，

> - `claim_task`（抢一个没人领的）：`WHERE id=? AND status=? AND assigned_agent_id IS NULL`
> - `reassign_task`（用户显式改派）：`WHERE id=? AND assigned_agent_id=?旧值`
> - `release_task_agent`（释放）：`WHERE id=? AND assigned_agent_id=?`
>
> 条件不成立就**明确失败**，不静默覆盖。任务号 W-07～W-12。

### B5 ✅ 量到并记录（2026-10-19 新增）：甘特图在夏令时时区会漂

- **量法**：探针脚本，8 个时区（UTC / Asia-Shanghai / Asia-Tokyo / America-New_York /
  America-Los_Angeles / Europe-Berlin / Australia-Sydney / Pacific-Kiritimati）

- **结论（两条，都只影响"有夏令时"的时区）**：
  1. **任务条定位**：192 组里有 **10 组**在美东/美西时区偏了**一格**
     （`left` 差 1 天的像素），且都出现在跨夏令时切换点附近。
     **UTC+8（Asia/Shanghai）恒定**，中国大陆用户不受影响。
  2. **时间轴长度**：`totalDays` 用「毫秒差 / 一天」向上取整，

     于是 `totalDays = viewDays + 1`（美东/美西/柏林实测 121，UTC/上海/东京 120）。
- **处理**：**只量清楚，不改行为**（任务号 W-16）。
  改成"按日历天算"会挪动任务条位置，属于**用户可见的产品变化**，
  本轮不擅自做 —— 记在这里交给决策人。

## C. 工程基线

### C1 ✅ 我自己查错的一条，撤案：tsconfig 其实没问题

**本条先记经过，因为它差点留在文档里变成一个假缺陷。**

- 我最初用 `npx tsc --noEmit -p tsconfig.json`，报两条错：
  `TS5102: Option 'baseUrl' has been removed` 与 `TS5090`。
  又用 `git stash` 前后对拍，确认"不是最近改动引入"，于是准备当成**既存缺陷**写进 01。
- 但 CI 第 44 行 `npm run typecheck` 是**硬步骤**（不是 `continue-on-error`），
  一个真会让 `tsc` 直接失败的 tsconfig 不可能长期绿。**两处矛盾，必有一处我错了。**
- 查下去：`package.json` 声明 `typescript: ^5.6.0`，
  `package-lock.json` 实际解析到 **5.9.3**；
  而我本机 `npx tsc --version` 报的是 **7.0.2** ——
  `node_modules` 没装时 `npx` 会**直接抓最新版**，绕过了 lockfile。
- 装上依赖（`npm ci`）后用锁定版本重跑：

      $ ./node_modules/.bin/tsc --version
      Version 5.9.3
      $ npm run typecheck
      (无输出，rc=0)

- **结论：tsconfig 是对的，`baseUrl` 在 5.9.3 里只是废弃、并未移除；
  报错的 TypeScript 7 才真的移除了它。那两条错是本机环境的假象。**

**教训（本仓特有，写在这里免得下一个人再踩）**：
在**没装 `node_modules`** 的仓里跑 `npx tsc` / `npx <任意工具>`，
拿到的是**最新版工具**，不是 lockfile 定的版本。判据：
**本机 `npx <tool> --version` ≠ 构建实际用的那个。**
先 `./node_modules/.bin/<tool> --version` 对一眼再下结论。
（本机已装：`typescript 5.9.3` 锁定 / `npx` 抓到 `7.0.2`）

- **量法**：`grep -rn "TaskDependency\|TaskAttachment\|WorkflowTemplate" src-tauri/src/`
  ⇒ 三个名字**只出现在各自的 `pub struct` 定义处**，零构造、零引用。
- **为什么是缺陷**：这三张表在 `init_schema` 里建了，
  读写走的是**裸 SQL**；而 Rust 侧又各放了一个"类型化镜像"结构体 ——
  也就是**同一份结构写了两遍**（一遍 DDL、一遍 struct）。
  字段一改就漂移，而编译器**不会报**（因为镜像根本没被用过）。
- **处理**：删掉三个结构体，在原位置留下注释说明
